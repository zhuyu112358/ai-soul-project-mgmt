## 一、核心理念

### 1.1 这是什么游戏？

**战策 Battleplan 是一款"灵魂指挥官"策略对战游戏。**

玩家不直接操控单位移动，而是作为**灵魂指挥官**，指挥自己培养的灵魂战队在魔法竞技场中进行自主战斗。玩家通过**战术指令、技能释放、战前配置**影响战斗走向，而灵魂单位则根据自身的**个性、元素属性、AI行为**自主移动、攻击、躲避和使用技能。

**一句话描述游戏体验：**
> "你是灵魂的指挥官，不是傀儡师。你的灵魂会自己战斗，而你决定它们如何战斗。"

### 1.2 核心设计哲学

| 原则 | 说明 |
|------|------|
| **灵魂自主** | 灵魂单位有自己的个性和战斗风格，会自主决策移动/攻击/躲避/技能 |
| **玩家策略** | 玩家通过战术指令（进攻/防守/集火/撤退）和技能释放影响战斗，不直接点选移动 |
| **战前深度** | 战斗前的灵魂选择、技能配置、战术预设是核心策略深度 |
| **战中紧张** | 战斗中玩家需要观察局势、适时释放技能、切换战术指令，有参与感和紧张感 |
| **成长反馈** | 战斗后灵魂获得经验和成长，玩家能看到自己培养的灵魂变强 |

### 1.3 玩家与灵魂的关系

玩家不是"操控者"，而是"指挥官"和"培养者"：

- **培养关系**：玩家在Ember灵魂引擎中培养灵魂，灵魂有自己的个性、元素属性、技能树
- **指挥关系**：战斗中玩家下达战术指令，灵魂根据指令调整行为倾向，但不被精确控制
- **信任关系**：玩家需要了解每个灵魂的个性和战斗风格，合理配置战队，信任灵魂的自主战斗
- **成长关系**：灵魂在战斗中获得经验，个性和能力会随成长变化

### 1.4 与传统RTS的区别

| 维度 | 传统RTS（星际/魔兽） | 战策 Battleplan |
|------|----------------------|-----------------|
| 单位控制 | 玩家直接点选移动/攻击 | 灵魂自主移动/攻击，玩家下达战术指令 |
| 操作密度 | 高APM，精确微操 | 低操作密度，策略决策为主 |
| 单位个性 | 无个性，同类型单位行为一致 | 每个灵魂有独特个性，影响战斗表现 |
| 战前配置 | 种族/建筑/科技选择 | 灵魂选择/技能配置/战术预设 |
| 战中操作 | 造兵/升级/微操/多线 | 技能释放/战术切换/战场互动 |
| 核心技巧 | 操作速度+多线能力 | 策略判断+灵魂理解+时机把握 |

### 1.5 目标玩家

- 喜欢策略游戏但不喜欢高强度微操的玩家
- 喜欢收集/培养角色的玩家
- 喜欢看"自己的队伍"战斗的玩家（类似自走棋但有更多参与感）
- 喜欢奇幻魔法主题的玩家

## 二、核心玩法循环

### 2.1 战斗中玩家做什么？

玩家在战斗中**不直接控制单位移动**，而是通过以下方式参与战斗：

#### 2.1.1 战术指令系统（核心）

玩家可以对**全体灵魂**或**单个灵魂**下达战术指令，改变AI行为倾向：

| 指令 | 效果 | 适用场景 |
|------|------|----------|
| **进攻 Aggressive** | 灵魂主动寻找敌人，优先攻击，冒进倾向高 | 优势局、需要快速推进 |
| **防守 Defensive** | 灵魂保持距离，优先躲避，防守反击 | 劣势局、需要拖时间 |
| **集火 Focus** | 灵魂优先攻击玩家标记的目标 | 需要击杀关键目标 |
| **撤退 Retreat** | 灵魂向后撤退，脱离战斗 | 血量危险、需要重整 |
| **跟随 Follow** | 灵魂跟随玩家指定的友方单位 | 保护核心单位 |
| **自由 Free** | 灵魂完全自主决策，不干预 | 默认状态 |

**操作方式**：底部战术栏有6个指令按钮，点击后选择目标（全体/单个灵魂），指令会在灵魂头顶显示图标。

#### 2.1.2 技能释放系统

玩家可以在战斗中**主动释放灵魂的技能**（类似MOBA的技能栏）：

- 每个灵魂有1-2个主动技能
- 技能有冷却时间和能量消耗
- 玩家点击技能图标，然后选择目标位置/目标单位
- 技能释放有视觉特效和音效

**M2简化**：每个灵魂1个主动技能，4个灵魂共4个技能，底部技能栏4个图标。

#### 2.1.3 战场互动

地图上有可互动元素，玩家可以触发：

| 互动元素 | 效果 | 操作 |
|----------|------|------|
| 魔法机关 | 触发区域伤害/治疗/增益 | 点击机关 |
| 补给点 | 恢复附近灵魂的生命/能量 | 灵魂走到补给点自动触发 |
| 可破坏物 | 破坏后获得增益/打开通路 | 灵魂攻击可破坏物 |
| 地形机关 | 升降桥/闸门，改变通路 | 点击开关 |

#### 2.1.4 观察与决策

玩家需要持续观察战场：

- 观察灵魂血量/能量状态
- 观察敌方灵魂位置和意图
- 观察技能冷却和可用时机
- 观察地形和互动元素状态
- 根据局势做出战术指令和技能释放决策

### 2.2 每场战斗的决策点

| 时间点 | 决策内容 |
|--------|----------|
| **战前** | 选择哪4个灵魂出战？配置什么技能？预设什么战术？选择哪张地图？ |
| **开局0-10秒** | 灵魂自动接战，玩家观察局势，决定是否切换初始战术 |
| **战斗中** | 何时集火？何时撤退？何时释放技能？是否触发战场机关？ |
| **关键团战** | 技能释放时机、集火目标选择、战术切换时机 |
| **残局** | 是否追击？是否防守？是否利用补给点？ |

### 2.3 战斗节奏

| 参数 | 值 | 说明 |
|------|-----|------|
| 单局时长 | **3-5分钟** | 快节奏，适合短时间游玩 |
| 灵魂数量 | 每方4个 | M2最小可玩规模 |
| 地图大小 | 中等竞技场 | 约30x20格 |
| 决策频率 | 每10-15秒一个重要决策 | 战术切换/技能释放 |
| 操作密度 | 低-中 | 不需要高APM，需要策略判断 |

### 2.4 核心循环图

```
战前配置 → 战斗开始 → 观察局势
    ↑                        ↓
灵魂成长 ← 战斗结算 ← 战术决策/技能释放
```

**战前**：选择灵魂→配置技能→预设战术→选择地图
**战中**：观察→决策（战术指令/技能释放/战场互动）→观察→决策...
**战后**：查看结果→灵魂获得经验→灵魂成长→回到菜单

### 2.5 战斗HUD布局

战斗界面采用**四周布局**，中央为战斗区域（灵魂自主战斗），四周为玩家操作UI：

```
┌─────────────────────────────────────────────────────────┐
│  [顶部状态栏]                                              │
│  [玩家方头像+血球]  VS  [时间]  VS  [AI方头像+血球]      │

│                    战斗区域（中央）                       │

│                                                         │
│                                                         │
├──────┬──────────────────────────────────────┬───────────┤
│[小地 │  [底部操作栏]                          │ [战斗日志] │
│ 图]  │  [战术指令栏: 进攻/防守/集火/撤退/跟随/自由] │  滚动列表 │

```

**各区域详细说明**：

| 区域 | 位置 | 内容 | 交互 |
|------|------|------|------|
| **顶部状态栏** | 顶部全宽 | 玩家方4个灵魂头像+血球+能量球（左），战斗时间（中），AI方4个灵魂头像+血球（右） | 点击头像查看详情（M3） |
| **战斗区域** | 中央 | 2D俯视角战斗场景，灵魂自主战斗，地形/障碍物/互动元素 | 点击互动元素触发，点击技能后点击目标 |
| **小地图** | 左下角 | 缩小版战场地图，显示灵魂位置（蓝点=玩家，红点=AI），地形概览 | 点击移动视角（M3，M2固定视角） |
| **战术指令栏** | 底部左侧 | 6个指令按钮：进攻/防守/集火/撤退/跟随/自由，当前指令高亮 | 点击指令→选择目标（全体/单个灵魂） |
| **技能栏** | 底部中央 | 4个技能图标（对应4个出战灵魂），显示冷却扇形遮罩+能量消耗 | 点击技能→进入瞄准→点击目标释放 |
| **暂停/设置** | 底部右侧 | 暂停按钮、设置按钮 | 点击打开暂停菜单/设置 |
| **战斗日志** | 右侧 | 滚动事件列表，重要事件（击杀/技能/暴击）高亮显示 | 自动滚动，不可交互 |

**数据可视化规范**（遵循ART_STYLE_GUIDE.md）：
- 生命值：球形血条（血球），绿色渐变填充，金色边框
- 能量值：球形能量条，蓝色渐变填充，金色边框
- 技能冷却：图标上扇形遮罩+倒计时数字
- 伤害飘字：向上浮动+渐隐，暴击金色放大
- 战术指令：灵魂头顶显示当前指令图标

## 三、灵魂AI行为系统

### 3.1 AI设计原则

- **自主决策**：灵魂会自己决定移动、攻击、躲避、技能使用
- **个性驱动**：不同个性的灵魂有不同的行为倾向
- **指令影响**：玩家的战术指令改变AI行为权重，不直接控制
- **可预测性**：玩家可以通过了解灵魂个性来预测其行为，做出策略决策
- **不蠢**：灵魂不会做出明显愚蠢的行为（如站着挨打、冲进敌群送死）

### 3.2 灵魂个性系统

每个灵魂有一个**主个性**，影响其战斗行为：

| 个性 | 战斗风格 | 行为倾向 | 适合角色 |
|------|----------|----------|----------|
| **激进 Aggressive** | 主动进攻，穷追不舍 | 优先攻击最近敌人，追击距离远，躲避倾向低 | 输出型/DPS |
| **保守 Defensive** | 保持距离，防守反击 | 优先躲避，保持攻击距离，追击距离短 | 远程/脆皮 |
| **灵巧 Agile** | 灵活走位，伺机而动 | 频繁移动，躲避倾向高，会绕后/侧翼 | 刺客/游击 |
| **坦克 Tank** | 顶在前面，吸引火力 | 优先靠近敌人，承受伤害，保护友方 | 前排/肉盾 |
| **辅助 Support** | 关注友方，提供增益 | 优先治疗/增益友方，站位靠后 | 治疗/辅助 |
| **平衡 Balanced** | 综合表现，无明显倾向 | 各项行为权重均衡 | 通用型 |

**个性如何影响AI决策**：
- AI决策时，每个候选行为（攻击/躲避/移动/技能）有基础权重
- 个性会调整这些权重（如激进型攻击权重+30%，躲避权重-20%）
- 战术指令进一步调整权重（如"防守"指令让所有灵魂躲避权重+50%）

### 3.3 AI决策流程

灵魂每**0.5-1.5秒**（个性影响决策间隔，激进型决策更快）进行一次决策：

```
1. 感知环境
   ├─ 扫描附近敌人（位置/血量/距离）
   ├─ 扫描附近友方（位置/血量）
   ├─ 检查自身状态（血量/能量/技能冷却）
   └─ 检查地形和互动元素

2. 评估候选行为
   ├─ 攻击：选择最优目标（距离/血量/威胁度）
   ├─ 移动：向目标移动/远离危险/占据有利位置
   ├─ 躲避：躲避敌方技能/远离危险区域
   ├─ 技能：是否使用技能，对谁使用
   └─ 互动：是否触发附近互动元素

3. 权重计算
   ├─ 基础权重（行为类型）
   ├─ 个性修正（+/-%）
   ├─ 战术指令修正（+/-%）
   ├─ 状态修正（血量低→躲避权重↑）
   └─ 环境修正（被集火→躲避权重↑）

4. 选择行为并执行
   └─ 权重最高的行为被选中，执行直到下次决策
```

### 3.4 玩家战术指令如何影响AI

战术指令**不直接控制**灵魂，而是**改变AI决策权重**：

| 指令 | 攻击权重 | 躲避权重 | 移动倾向 | 技能倾向 |
|------|----------|----------|----------|----------|
| 进攻 | +40% | -20% | 向敌人移动 | +20% |
| 防守 | -20% | +50% | 保持距离 | +10% |
| 集火 | +60%（目标） | -10% | 向目标移动 | +30%（目标） |
| 撤退 | -50% | +80% | 向基地移动 | -30% |
| 跟随 | -10% | +20% | 跟随目标 | +10% |
| 自由 | 0% | 0% | 自主 | 0% |

**关键设计**：指令是"倾向"不是"命令"。灵魂可能因为血量太低而在"进攻"指令下选择躲避，也可能因为敌人太近而在"撤退"指令下选择反击。这增加了不可预测性和趣味性。

### 3.5 灵魂状态机

```
IDLE（待机）
  ↓ 发现敌人
MOVING（移动）
  ↓ 进入攻击范围
ATTACKING（攻击）
  ↓ 血量低/被集火
EVADE（躲避）
  ↓ 技能可用+目标合适
CASTING（施法）
  ↓ 血量归零
DYING（死亡）
  ↓ 复活/战斗结束
IDLE
```

**状态切换条件**：
- IDLE → MOVING：发现敌人且不在攻击范围
- MOVING → ATTACKING：进入攻击范围
- ATTACKING → EVADE：血量<30% 或 被3个以上敌人攻击
- EVADE → ATTACKING：血量恢复>50% 且 敌人减少
- ANY → CASTING：技能可用且目标合适（个性影响技能使用倾向）
- ANY → DYING：血量归零

#### 3.5.1 AI行为树详细设计

灵魂AI采用**优先级行为树**结构，每次决策时从高优先级到低优先级依次检查，第一个满足条件的行为被执行。

```
AI决策根节点（优先级从高到低）
│
├─ 1. 死亡检查（最高优先级）
│   └─ 条件：HP <= 0 → 进入DYING状态
│
├─ 2. 战术指令：撤退
│   ├─ 条件：玩家下达"撤退"指令
│   └─ 行为：向己方基地移动，躲避敌人，不主动攻击
│
├─ 3. 低血量自保
│   ├─ 条件：HP < 25% 且 附近有敌人
│   └─ 行为：EVADE躲避，向最近补给点移动，使用治疗/防御技能（如有）
│
├─ 4. 战术指令：集火
│   ├─ 条件：玩家下达"集火"指令且目标存活
│   └─ 行为：向集火目标移动，进入范围后攻击，优先对目标使用技能
│
├─ 5. 技能释放判断
│   ├─ 条件：技能可用（冷却结束+能量充足）且有合适目标
│   ├─ 子判断（按技能类型）：
│   │   ├─ 治疗技能：友方HP < 50% → 释放
│   │   ├─ 防御技能：自身HP < 40% 或 被集火 → 释放
│   │   ├─ 控制技能：敌方聚集（≥3个）→ 释放
│   │   ├─ 伤害技能：目标在范围内 → 释放
│   │   └─ 位移技能：追击残血（敌方HP<20%）或 逃离危险 → 释放
│   └─ 行为：CASTING施法，进入技能前摇→释放→后摇
│
├─ 6. 战术指令：防守
│   ├─ 条件：玩家下达"防守"指令
│   └─ 行为：保持与敌人距离（远程攻击范围），优先躲避，防守反击
│
├─ 7. 战术指令：跟随
│   ├─ 条件：玩家下达"跟随"指令
│   └─ 行为：跟随指定友方单位，保持距离，攻击附近敌人
│
├─ 8. 战术指令：进攻
│   ├─ 条件：玩家下达"进攻"指令
│   └─ 行为：主动寻找最近敌人，向敌人移动，进入范围后攻击
│
├─ 9. 默认：自由（自主决策）
│   ├─ 条件：无特殊指令或"自由"指令
│   └─ 行为：按个性自主决策（激进型主动进攻/保守型保持距离/灵巧型游走/坦克型顶前/辅助型跟随治疗）
│
└─ 10. 战场互动（低优先级，条件合适时触发）
    ├─ 条件：附近有互动元素且需要（补给点→血量低，能量水晶→能量低，宝箱→无敌人干扰）
    └─ 行为：移动到互动元素位置，触发互动
```

#### 5.7.2 伤害计算公式

```
最终伤害 = (攻击力 × 技能倍率 - 防御力 × 0.5) × 元素克制系数 × 暴击系数 × 随机系数

其中：
- 技能倍率：普通攻击=100%，技能=150%-300%
- 元素克制系数：克制=125%，被克=80%，无关系=100%（M2可选）
- 暴击系数：暴击=暴击伤害（150%），不暴击=100%
- 随机系数：90%-110%（防止伤害完全可预测）
- 最小伤害：攻击力 × 10%（防止高防御导致0伤害）
```

**治疗计算公式**：
```
最终治疗 = 治疗基础值 × (1 + 攻击力 × 0.02) × 随机系数
```

**伤害减免**：
```
实际受到伤害 = 最终伤害 × (100 / (100 + 防御力))
```
（防御力每增加100点，伤害减免约50%，避免防御堆叠无敌）

     - 范围技能：鼠标位置显示范围圈（金色半透明）
     - 单体技能：鼠标悬停敌人显示目标标记
     - 方向技能：显示方向箭头
   - 玩家点击目标位置/目标单位释放技能
   - 技能进入冷却（图标上扇形遮罩+倒计时数字）
   - 能量不足时技能图标变灰，不可点击
   - 右键或ESC取消瞄准

2. **战术指令流程**：
   - 玩家点击战术指令栏按钮（进攻/防守/集火/撤退/跟随/自由）
   - "集火"和"跟随"需要选择目标：
     - 点击"集火"→点击敌方灵魂→所有友方灵魂集火该目标
     - 点击"跟随"→点击友方灵魂→其他灵魂跟随该目标
   - 其他指令直接生效（全体）
   - 当前指令按钮高亮显示
   - 灵魂头顶显示当前指令图标（小图标）

3. **战场互动流程**：
   - 玩家点击战场上的互动元素（魔法机关/补给点/宝箱/升降桥）
   - 如果互动元素在可操作范围内，直接触发
   - 如果超出范围，最近的友方灵魂会移动过去触发
   - 互动元素有冷却时间，冷却中显示倒计时

4. **暂停菜单**：
   - 点击暂停按钮或按ESC打开暂停菜单
   - 暂停菜单选项：继续战斗/重新开始/设置/返回主菜单
   - 暂停时战斗停止，灵魂静止
   - 练习模式下暂停菜单额外有"重置战斗"选项

### 6.3 灵魂成长循环

```
战斗 → 获得经验 → 升级 → 属性提升 → 更强的战斗 → 更多经验
```

- 每个出战灵魂获得经验（胜利×2，失败×1）
- 升级提升血量/攻击/防御基础属性
- M2不实现技能解锁/天赋树/进化，这些留到M3/M4

### 6.5 典型战斗时间线

以一局**4v4快速对战**（普通难度AI，以太神殿地图）为例：

```
0:00  战斗开始
      ├─ 双方灵魂从基地出发，自主向中央移动
      ├─ 玩家观察双方阵容，决定初始战术（默认"自由"）
      └─ 灵魂进入战斗区域，开始接战

0:00-0:30  初期接触
      ├─ 前排（坦克/近战）率先交火
      ├─ 后排（远程/治疗）保持距离输出
      ├─ 玩家观察局势，可能切换"进攻"或"防守"指令
      └─ 第一个技能冷却完成（约6-10秒）

0:30-1:30  中期团战
      ├─ 双方技能交替释放，血量开始下降
      ├─ 玩家关键决策点：
      │   ├─ 是否集火敌方脆皮？（"集火"指令）
      │   ├─ 是否释放治疗技能拯救残血灵魂？
      │   ├─ 是否触发中央魔法机关？
      │   └─ 血量危险时是否"撤退"重整？
      ├─ 可能出现首次击杀（约1-1.5分钟）
      └─ 战场互动元素首次可用（补给点30秒冷却）

1:30-3:00  后期决战
      ├─ 双方人数减少，形成多打少局面
      ├─ 存活灵魂等级提升（战斗中临时属性增长，M3+）
      ├─ 玩家持续决策：
      │   ├─ 优势方："进攻"推进，扩大优势
      │   ├─ 劣势方："防守"拖时间，寻找反击机会
      │   └─ 均势方：技能释放时机决定胜负
      ├─ 补给点第二次可用（90秒冷却后）
      └─ 可能出现决定性击杀

3:00-5:00  战斗结束
      ├─ 一方全部被击败 → 立即结束
      ├─ 或5分钟时间到 → 按剩余血量总和判定胜负
      ├─ 战斗结算界面：
      │   ├─ 胜利/失败展示
      │   ├─ 战斗数据（伤害/治疗/承受伤害/KDA）
      │   ├─ 灵魂经验获得和升级
      │   └─ 奖励展示
      └─ 玩家选择：再次战斗 / 返回菜单 / 查看灵魂详情
```

**关键决策点分布**：
- 每15-30秒一个重要决策（战术切换/技能释放）
- 每1分钟一个关键节点（首次击杀/补给点/魔法机关）
- 玩家操作密度：低-中（不需要高APM，但需要持续观察和决策）

#### 7.5.2 引导设计原则

| 原则 | 说明 |
|------|------|
| **边玩边学** | 引导在真实战斗中进行，不是单独的教程关卡 |
| **强制操作** | 关键操作（战术/技能/互动）强制玩家亲手操作一次 |
| **可跳过** | 玩家可以随时跳过引导（设置中关闭引导） |

| **简洁** | 每步提示不超过2句话，避免信息过载 |

## 附录A：平衡性测试方案

### A.1 测试目标

确保M2中8个灵魂、6种战术指令、8个技能在不同组合下的胜率接近50%，没有明显过强或过弱的组合。

### A.2 测试用例

| 测试ID | 测试内容 | 方法 | 通过标准 |
|--------|----------|------|----------|
| BAL_001 | 单灵魂1v1平衡 | 每个灵魂vs其他7个灵魂各100场AI对战 | 每个灵魂胜率35%-65% |
| BAL_002 | 标准队vs标准队 | 土+火+雷+水 vs 相同阵容100场 | 双方胜率45%-55% |
| BAL_003 | 激进队vs防守队 | 火+风+雷+暗 vs 土+冰+水+光 各100场 | 双方胜率40%-60% |
| BAL_004 | 技能伤害平衡 | 8个技能DPS计算（伤害/冷却） | 技能DPS差异不超过30% |
| BAL_005 | 战术指令效果 | 6种指令vs默认自由各100场 | 每种指令胜率40%-60% |
| BAL_006 | AI难度梯度 | 简单vs普通vs困难各50场 | 简单胜率>60%，普通40%-60%，困难<40% |
| BAL_007 | 地图平衡 | 以太神殿vs水晶洞穴各100场 | 双方胜率45%-55%（无地图优势） |
| BAL_008 | 游戏时长 | 100场战斗平均时长 | 平均3-5分钟，不超过8分钟 |

### A.3 数值调整流程

```
发现不平衡（胜率<35%或>65%）
  ↓
分析原因（属性过高/技能过强/个性权重不合理）
  ↓
调整数值（属性±5-10%，技能伤害±10-15%，冷却±1-2秒）
  ↓
重新运行测试用例
  ↓
通过标准 → 确认调整
不通过 → 继续调整（最多3轮）
```

### A.4 关键数值监控指标

| 指标 | 理想值 | 警告阈值 |
|------|--------|----------|
| 单灵魂最高胜率 | <60% | >65% |
| 单灵魂最低胜率 | >40% | <35% |
| 技能DPS最大值/最小值 | <1.3 | >1.5 |
| 平均战斗时长 | 4分钟 | >6分钟或<2分钟 |
| 首杀平均时间 | 1-1.5分钟 | >2分钟或<30秒 |

## 附录B：常见问题解答（FAQ）

### B.1 玩法相关

**Q: 玩家完全不控制灵魂移动吗？**
A: 是的。灵魂自主移动、攻击、躲避、使用技能。玩家通过战术指令（改变AI行为倾向）和技能释放（主动释放技能）参与战斗，不直接点击移动单位。

**Q: 战术指令是直接命令还是建议？**
A: 是"倾向"不是"命令"。战术指令改变AI行为的权重，灵魂仍会根据个性和战场情况自主决策。例如"进攻"指令让灵魂更主动攻击，但低血量时仍会躲避。

**Q: 一局战斗多长时间？**
A: 3-5分钟。一方全部被击败立即结束，或5分钟时间到按剩余血量总和判定胜负。

**Q: 可以暂停战斗吗？**
A: 可以。点击暂停按钮或按ESC打开暂停菜单，可选继续/重开/设置/返回主菜单。

### B.2 灵魂相关

**Q: 灵魂从哪里来？**
A: M2预设8个灵魂供玩家选择。M3+将与Ember灵魂引擎联动，玩家培养的灵魂可以作为战斗单位出场。

**Q: 灵魂如何变强？**
A: 战斗后获得经验，升级提升HP/ATK/DEF基础属性。M2不实现技能解锁/天赋树/进化，这些留到M3/M4。

**Q: 灵魂死亡后会怎样？**
A: M2不实现复活。灵魂死亡后变为观战状态，战斗结束后自动复活。M3+可能添加复活机制。

**Q: 6种个性有什么区别？**
A: 个性影响AI行为权重：激进型更主动进攻、保守型更注重躲避、灵巧型游走绕后、坦克型顶在最前、辅助型跟随治疗、平衡型均衡。详见3.4节和3.5.1节。

### B.3 技术相关

**Q: 游戏用什么引擎？**
A: Godot引擎。现有代码基础较好，M2核心战斗系统可在2-3周内实现。

**Q: 支持什么平台？**
A: M2优先PC（Windows），Steam EA上架。M3+考虑移植到其他平台。

**Q: 像素风游戏的性能如何？**
A: 2D像素风性能要求低，同屏8个灵魂+特效可稳定60FPS。详见附录C性能优化方案。

**Q: 支持多人对战吗？**
A: M2只支持AI对战。M3+添加玩家对战（排位赛/匹配）。

### B.4 开发相关

**Q: M2什么时候能完成？**
A: 按开发里程碑规划，M2总工期14-21天（2-3周）。详见7.7节。

**Q: M2完成后做什么？**
A: M3添加：玩家对战、更多灵魂、更多地图、天赋树、技能解锁、隐藏成就。M4添加：进化系统、剧情模式、排位赛、合作模式。

**Q: 如何报告Bug或建议？**
A: GitHub Issues（management仓库和battleplan仓库），或在战策DEVLOG中标记[设计需求]/[Bug]。

## 附录C：性能优化方案

### C.1 帧率目标

- **目标帧率**：60FPS（PC端）
- **最低帧率**：30FPS（低端设备）
- **同屏灵魂数**：最多8个（4v4）
- **同屏特效数**：最多20个（技能特效+粒子）

### C.2 优化措施

| 优化项 | 方法 | 预期效果 |
|--------|------|----------|
| 精灵图合批 | 所有灵魂精灵图合并为Sprite Sheet，减少Draw Call | Draw Call减少50%+ |
| 粒子限制 | 同屏粒子数上限200，超出自动回收最旧粒子 | 避免粒子爆炸导致卡顿 |
| 对象池 | 灵魂/特效/伤害飘字使用对象池，避免频繁创建销毁 | GC减少80%+ |
| LOD | 远处灵魂简化动画（4帧→2帧），小地图用简化图标 | 渲染开销减少30% |
| 碰撞优化 | 使用AABB粗检+圆形精检，避免每帧全量碰撞检测 | 碰撞计算减少60% |
| AI降频 | AI决策间隔0.5-1.5秒（按个性），不是每帧决策 | CPU开销减少70%+ |
| 音频预加载 | 所有音效启动时预加载，战斗中不加载 | 避免战斗中卡顿 |
| 地图分层 | 背景/地形/障碍物/灵魂/特效/UI分层渲染 |  Overdraw减少 |

### C.3 内存管理

| 资源类型 | 内存预算 | 管理方式 |
|----------|----------|----------|
| 精灵图 | <50MB | Sprite Sheet合并，按需加载 |
| 地图瓦片 | <20MB | 当前地图加载，切换时卸载 |
| 音效 | <30MB | 预加载核心音效，其他按需加载 |
| UI资源 | <20MB | 启动时加载，常驻内存 |
| **总计** | **<120MB** | — |

### C.4 加载优化

- **启动加载**：<3秒（预加载UI+核心音效+主菜单资源）
- **战斗加载**：<1秒（加载地图+灵魂精灵图+战斗音效）
- **异步加载**：灵魂精灵图/地图瓦片异步加载，加载时显示占位
- **进度条**：加载时显示进度条+提示文字

## 附录F：存档系统设计

### F.1 存档内容

| 数据类型 | 内容 | 保存时机 |
|----------|------|----------|
| 灵魂数据 | 所有灵魂的等级/经验/属性/技能配置 | 战斗结算后自动保存 |

| 战斗记录 | 最近10场战斗的结果和数据 | 战斗结算后保存 |
| 新手引导 | 引导完成状态 | 引导完成后保存 |

### F.2 存档方式

| 方式 | 说明 | M2实现 |
|------|------|--------|
| **自动存档** | 关键操作后自动保存，无需玩家手动操作 | ✅ M2实现 |
| **手动存档** | 玩家按F5或在设置中点击保存 | ✅ M2实现 |
| **多存档位** | 3个存档位，可选择覆盖或新建 | ❌ M3（M2单存档） |
| **云存档** | Steam云同步，跨设备同步 | ❌ M3（M2本地存档） |
| **存档回滚** | 回滚到之前的存档点 | ❌ M4 |

### F.3 存档文件结构

```
save/
  ├── player_data.json      # 玩家进度和设置
  ├── souls/
  │   ├── fire_soul.json    # 火灵魂数据
  │   ├── water_soul.json   # 水灵魂数据
  │   └── ...
  ├── battle_records/
  │   ├── record_001.json   # 最近战斗记录
  │   └── ...
  └── meta.json              # 存档元信息（版本/时间/校验）
```

### F.4 存档安全

| 措施 | 说明 |
|------|------|
| **版本兼容** | 存档文件包含版本号，新版本自动迁移旧存档 |
| **数据校验** | 存档文件包含校验和，防止数据损坏 |
| **备份机制** | 保存时先写临时文件，成功后替换原文件，防止写入中断 |
| **错误恢复** | 存档损坏时自动加载备份，或重置为初始状态 |
| **防作弊** | 关键数据（灵魂等级/成就）包含签名验证（M3+） |

### F.5 数据统计

游戏自动收集以下统计数据（本地保存，不上传）：
- 总战斗次数/胜率/平均时长
- 每个灵魂的出场次数/胜率/KDA
- 每个战术指令的使用次数/胜率
- 每个技能的释放次数/命中率/总伤害

## 附录G：数据分析方案

### G.1 数据收集目标

通过收集玩家行为数据，用于：
1. 平衡性调整（识别过强/过弱的灵魂/技能/战术）
2. 体验优化（识别玩家流失点/困惑点）
3. 内容规划（了解玩家偏好，指导后续开发）

### G.2 需要收集的数据

| 数据类别 | 具体指标 | 用途 |
|----------|----------|------|
| **战斗数据** | 战斗时长/胜负/双方阵容/使用的战术/释放的技能 | 平衡性分析 |
| **灵魂数据** | 每个灵魂的出场率/胜率/平均KDA/击杀数/死亡数 | 灵魂平衡 |
| **技能数据** | 每个技能的释放次数/命中率/总伤害/击杀贡献 | 技能平衡 |
| **战术数据** | 每种战术指令的使用频率/胜率/持续时间 | 战术平衡 |
| **地图数据** | 每张地图的游玩次数/胜率/平均时长 | 地图平衡 |
| **玩家行为** | 菜单停留时间/战斗配置时间/暂停次数/退出时机 | 体验优化 |
| **新手引导** | 引导完成率/每步停留时间/跳过率 | 引导优化 |
| **性能数据** | 平均帧率/最低帧率/加载时间/崩溃率 | 性能优化 |

### G.3 数据收集方式

| 方式 | 说明 | M2实现 |
|------|------|--------|
| **本地日志** | 所有数据本地保存为JSON日志文件 | ✅ M2实现 |
| **匿名上传** | 玩家可选是否上传匿名数据（默认关闭） | ❌ M3（需隐私政策） |
| **数据导出** | 玩家可导出自己的游戏数据 | ❌ M3 |
| **开发者控制台** | 开发版本内置数据查看和分析工具 | ✅ M2实现（开发版） |

### G.4 平衡性分析流程

```
收集战斗数据（每局结束后）
  ↓
数据清洗（去除异常值/测试数据）
  ↓
计算指标（胜率/出场率/KDA/DPS等）
  ↓
识别异常（胜率>65%或<35%，出场率>50%或<5%）
  ↓
分析原因（属性/技能/个性/战术/地图）
  ↓
调整数值（属性±5-10%，技能±10-15%）
  ↓
A/B测试（新旧版本对比，验证调整效果）
  ↓
确认调整或回滚
```

### G.5 关键平衡指标阈值

| 指标 | 理想范围 | 警告阈值 | 需调整阈值 |
|------|----------|----------|------------|
| 灵魂胜率 | 45%-55% | 40%-60% | <35%或>65% |
| 灵魂出场率 | 10%-30%（8个灵魂） | 5%-40% | <5%或>50% |
| 技能胜率差 | <10% | 10%-20% | >20% |
| 战术胜率 | 45%-55% | 40%-60% | <35%或>65% |
| 地图胜率差 | <5% | 5%-10% | >10% |
| 平均战斗时长 | 3-5分钟 | 2-6分钟 | <2分钟或>8分钟 |

### G.6 隐私保护

- 所有数据匿名化，不包含个人身份信息
- 数据上传需玩家明确同意（默认关闭）
- 玩家可随时查看和删除自己的数据
- 数据仅用于游戏平衡性和体验优化，不用于广告或第三方共享
- 遵循GDPR/CCPA等隐私法规（M3+正式上线时）
