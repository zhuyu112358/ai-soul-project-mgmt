# SoulArena 架构约束（灵魂系统内核边界）

**版本：** v1.0
**适用仓库：** zhuyu112358/SoulArena
**维护方：** AI灵魂项目监控任务

> 本文档定义SoulArena灵魂系统内核的硬性架构边界。监控任务每次巡检源码，发现越界立即标记为耦合风险。开发时必须遵守。

---

## 一、核心定位

SoulArena是**通用灵魂认知引擎**，负责：
- 认知/心理/情绪/记忆/决策等通用灵魂能力
- 对外提供标准化的感知输入和动作输出接口
- 灵魂状态的持久化和序列化

SoulArena**不负责**：
- 具体灵魂的人设、剧情、背景故事
- 具体游戏世界的规则、地图、物体属性
- 世界物理模拟、渲染、网络同步
- 具体灵魂实例的业务逻辑

---

## 二、硬性边界（禁止越界）

### 2.1 禁止硬编码具体灵魂人设

❌ **禁止：**
- 在 `server/soul/` 内核代码中写入具体灵魂的名字、性格设定、背景故事
- 硬编码特定灵魂ID的特殊逻辑（如 `if (soulId === 'xxx') { ... }`）
- 在内核中为某个灵魂定制专属行为

✅ **允许：**
- 通过配置文件/外部输入加载灵魂参数
- 通用的性格参数系统（如大五人格维度），具体数值由外部传入
- 单元测试中使用mock灵魂实例（测试代码除外）

### 2.2 禁止硬编码具体世界属性

❌ **禁止：**
- 在内核中写入具体世界的地图名称、物体属性、游戏规则
- 硬编码世界ID的特殊处理逻辑
- 依赖特定世界的物理参数（如重力值、地图尺寸）

✅ **允许：**
- 通过 `worldContext` / `worldConfig` 接收世界传入的参数
- 通用的感知解析逻辑（不依赖具体世界格式）
- WorldInterface层做格式转换（WorldInterface是边界层，不属于内核）

### 2.3 禁止内核直接依赖世界引擎

❌ **禁止：**
- `server/soul/` 下的认知系统直接import或require世界引擎的代码
- 认知系统直接调用世界API（必须通过WorldInterface边界层）
- 内核代码中出现世界特定的数据结构

✅ **允许：**
- WorldInterface.js作为唯一边界层，负责世界感知→认知输入的转换
- 认知系统只处理标准化的 `worldContext` 格式
- 通过webhook/回调输出动作，不直接调用世界API

### 2.4 禁止业务逻辑混入内核

❌ **禁止：**
- 在内核中实现具体游戏的战斗规则、经济系统、任务系统
- 为特定产品（如RTS对战、养成世界）写专属逻辑
- 商业化逻辑（付费、交易、通行证）出现在内核中

✅ **允许：**
- 通用的决策系统（如价值评估、风险判断），具体决策由外部场景触发
- 通用的学习/适应机制，不绑定具体游戏规则

## 三、模块分层规范

```
server/soul/
├── Soul.js                    # 灵魂核心（只做认知调度，不做业务逻辑）
├── WorldInterface.js          # ⭐ 唯一边界层：世界感知转换 + 动作输出
├── ConversationManager.js     # 对话管理（通用，不绑定具体场景）
├── SoulEvaluator.js           # 评估系统（通用指标）
├── 认知子系统/                 # 46+通用认知系统（注意力/记忆/情绪/决策等）
└── utils/                     # 工具函数
```

**分层规则：**
1. 认知子系统只能依赖Soul.js传入的标准化数据，不能直接访问世界
2. WorldInterface是唯一允许接触世界格式的模块
3. 新增认知系统必须是通用能力，不能为特定灵魂/世界定制
4. 具体灵魂实例的数据存储在 `souls/` 数据目录，不写入内核代码

---

## 四、接口规范

### 4.1 感知输入（世界→灵魂）

- 唯一入口：`WorldInterface.processPerception(soulId, perceptionData, soul)`
- 感知格式遵循 `docs/interface_spec.md` 定义
- 认知系统只接收 `worldContext`（标准化格式），不直接接收原始感知

### 4.2 动作输出（灵魂→世界）

- 唯一出口：WorldInterface通过 `callbackUrl` webhook发送动作
- 动作格式遵循 `docs/interface_spec.md` 定义
- 认知系统不直接输出世界特定的动作指令

### 4.3 生命周期

- `enter-world` / `exit-world` 通过WorldInterface管理
- 灵魂进入/离开世界不影响认知系统的内部状态

## 五、巡检清单（监控任务每次执行）

监控任务每次巡检以下项，发现问题记录到BLOCKERS.md：

- [ ] `server/soul/` 内核代码中是否出现具体灵魂名字/ID的硬编码
- [ ] 内核代码中是否出现具体世界名称/地图/物体的硬编码
- [ ] 认知子系统是否直接import了世界引擎代码
- [ ] 是否有 `if (soulId === 'xxx')` 形式的特殊逻辑
- [ ] WorldInterface是否仍是唯一的世界边界层
- [ ] 新增系统是否为通用认知能力（非特定灵魂/世界定制）
- [ ] 接口实现是否对齐 `docs/interface_spec.md`

---

## 六、违规处理

1. 发现越界代码 → 记录到BLOCKERS.md，标记为耦合风险
2. 评估影响范围 → 提出重构建议（将业务逻辑移到边界层或外部配置）
3. 在下一轮开发中修复 → 修复后从卡点清单移除
4. 反复违规 → 考虑在开发定时任务prompt中加强约束
