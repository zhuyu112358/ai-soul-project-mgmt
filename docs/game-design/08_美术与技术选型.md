## 一、美术风格选型

### 1.1 候选美术风格对比

| 风格 | 代表作品 | 优点 | 缺点 | 适配度 |
|------|----------|------|------|--------|
| **2D像素风** | 星露谷物语、挺进地牢、我的世界 | 制作成本低、风格统一、怀旧感强、性能要求低、Steam独立游戏友好 | 表现力有限、角色细节少、移动端UI适配难、可能显得"廉价" | ★★★★☆ |
| **2D手绘风** | 空洞骑士、奥日、哈迪斯 | 美术品质高、角色表现力强、情感传达好、适合灵魂的细腻情绪 | 制作成本高、动画工作量大、风格统一难度高、周期长 | ★★★☆☆ |
| **低多边形3D** | 纪念碑谷、无人深空、Tunic | 风格独特、制作成本中等、3D空间感强、可旋转视角 | 角色表情表现力弱、需要3D制作能力、性能要求中等 | ★★★☆☆ |
| **3D卡通渲染** | 宝可梦剑盾、动物森友会、原神 | 表现力最强、角色细节丰富、3D空间感强、商业价值高 | 制作成本极高、需要专业3D团队、性能要求高、周期长 | ★★☆☆☆ |
| **2.5D（2D角色+3D场景）** | 八方旅人、三角战略 | 2D角色的细腻+3D场景的空间感、风格独特 | 技术复杂度高、2D与3D融合难度大、制作成本中等偏高 | ★★★☆☆ |

### 1.2 推荐方案：2D像素风（阶段一）→ 2D手绘风升级（阶段二）

**阶段一（RTS对战，0-9月）：2D像素风**

选择理由：
1. **制作成本最低** — 1-3人小团队可以承担，像素美术可以外包/采购/AI辅助生成
2. **开发速度最快** — 像素资源制作周期短，可以快速迭代
3. **Steam独立游戏友好** — 像素风在Steam独立游戏社区有大量受众，接受度高
4. **性能要求低** — 2D像素渲染对硬件要求极低，确保多灵魂同屏时的流畅度
5. **RTS俯视角适配好** — 俯视角RTS不需要角色面部细节，像素风完全够用
6. **AI辅助生成成熟** — 像素风格的AI生成工具（如Aseprite+AI插件）已经比较成熟，可以大幅提升产能

**阶段二（养成+直播，9-18月）：2D手绘风升级**

升级理由：
1. **养成阶段需要更强的情感传达** — 玩家需要看到灵魂的细腻情绪（表情、动作），像素风表现力不足
2. **移动端用户对美术品质要求更高** — 养成类游戏的主要用户（女性/休闲玩家）对美术品质敏感
3. **直播画面需要更高的视觉品质** — 直播场景需要更精美的画面才能吸引观众
4. **阶段一有收入后可以投入更多美术资源** — 阶段一盈利后可以招聘美术或外包高品质手绘资源

**升级策略：**
- 不是完全重做，而是"高清化"——保留像素风的构图和设计，升级为手绘风格
- 灵魂角色优先升级（情感传达的核心），场景和UI后续升级
- 支持"像素风/手绘风"切换，让玩家选择自己喜欢的风格

### 1.3 美术风格定义

**阶段一像素风定义：**

| 维度 | 规格 |
|------|------|
| 分辨率 | 基础32×32像素/格，角色64×64像素 |
| 色板 | 每个角色限32色，场景限64色，整体色调偏暖 |
| 动画 | 每个角色8方向行走动画（4方向+镜像），攻击/受击/待机各2-4帧 |
| 特效 | 粒子特效+帧动画，单特效不超过16帧 |
| UI | 像素风UI，圆角边框，清晰的图标和文字 |
| 整体氛围 | 温暖、奇幻、略带神秘感，避免暗黑/恐怖风格 |

**色彩设计原则：**
- 灵魂角色使用高饱和度、高对比度的配色，确保在复杂场景中清晰可见
- 不同个性的灵魂有不同的色彩倾向（勇敢=红/橙、谨慎=蓝/绿、好奇=紫/黄、友善=粉/青）
- 场景使用中等饱和度，避免与角色冲突
- UI使用中性色（灰/白/深蓝），突出游戏内容

## 二、角色设计：灵魂的视觉表现

### 2.1 灵魂的视觉设计理念

灵魂是AI灵魂游戏的核心，其视觉设计需要传达以下信息：
1. **这是一个"有生命"的存在** — 不是机器，不是道具，而是有灵魂的生命
2. **个性可视化** — 从外观就能看出灵魂的性格倾向
3. **情绪可感知** — 灵魂的情绪变化能通过视觉表现出来
4. **可定制性** — 玩家可以自定义灵魂的外观，体现独特性
5. **跨游戏一致性** — 灵魂在不同产品/不同美术风格中保持可识别的核心特征

### 2.2 灵魂的基础形态

**设计方案："能量核心+形态外壳"双层结构**

```
┌─────────────────────────────────┐
│         灵魂的视觉结构            │
│                                 │
│    ╭─────────────────────╮      │
│    │   形态外壳（可定制）  │      │
│    │   · 身体形状         │      │
│    │   · 颜色/纹理        │      │
│    │   · 装饰/饰品        │      │
│    │   · 表情/眼睛        │      │
│    │                     │      │
│    │    ┌───────────┐    │      │
│    │    │ 能量核心    │    │      │
│    │    │ （不可定制） │    │      │
│    │    │ · 脉动光效  │    │      │
│    │    │ · 颜色随情绪 │    │      │
│    │    │ · 粒子环绕   │    │      │
│    │    └───────────┘    │      │
│    ╰─────────────────────╯      │
│                                 │
│  能量核心是灵魂的"灵魂"，形态外壳是灵魂的"身体" │
└─────────────────────────────────┘
```

**能量核心（不可定制部分）：**
- 灵魂中心的发光核心，持续脉动
- 核心颜色随情绪变化（平静=蓝、兴奋=黄、愤怒=红、悲伤=紫、恐惧=白）
- 核心周围有粒子环绕，粒子密度和运动速度随情绪变化
- 核心是灵魂的"生命体征"——核心熄灭=灵魂被击败/出局
- 所有灵魂的核心结构相同，这是"灵魂"的统一标识

**形态外壳（可定制部分）：**
- 包裹能量核心的身体形态，可以是各种形状（球形、人形、兽形、抽象形）
- 玩家可以自定义外壳的形状、颜色、纹理、装饰
- 外壳有表情系统（眼睛、嘴巴），能表达基本情绪
- 外壳有动画系统（行走、攻击、受击、待机、互动）
- 外壳是"皮肤"系统的载体——玩家可以购买/创作不同的外壳

### 2.3 个性与外观的关联

灵魂的外观与其个性有一定关联，但不是强制的——玩家可以自由定制：

| 个性维度 | 推荐外观特征 | 说明 |
|----------|-------------|------|
| 勇敢 | 锐利的棱角、暖色调（红/橙）、直立姿态 | 勇敢的灵魂外观更有攻击性 |
| 怯懦 | 圆润的形状、冷色调（蓝/绿）、低矮姿态 | 怯懦的灵魂外观更柔和 |
| 激进 | 尖锐的装饰、高饱和度、快速动画 | 激进的灵魂外观更有冲击力 |
| 保守 | 简洁的设计、低饱和度、缓慢动画 | 保守的灵魂外观更稳重 |
| 友善 | 圆润的表情、暖色调（粉/青）、开放姿态 | 友善的灵魂外观更可亲 |
| 孤僻 | 封闭的形状、暗色调、收敛姿态 | 孤僻的灵魂外观更内敛 |
| 好奇 | 复杂的装饰、多色搭配、灵动动画 | 好奇的灵魂外观更丰富 |
| 迟钝 | 简单的设计、单色调、缓慢动画 | 迟钝的灵魂外观更朴素 |

**设计要点：**
- 个性影响"推荐外观"，但玩家可以完全自由定制（外观与个性可以不一致，增加趣味性）
- 灵魂的"初始外观"由创建时的个性随机生成，玩家可以后续修改
- 稀有/限定外观有独特的视觉效果（粒子、光效、动画）

### 2.4 情绪的视觉表现

灵魂的情绪通过多个视觉通道同时表达：

| 情绪 | 能量核心 | 表情 | 姿态 | 粒子效果 | 动画速度 |
|------|----------|------|------|----------|----------|
| 平静 | 蓝色，缓慢脉动 | 中性表情 | 自然站立 | 少量粒子，缓慢环绕 | 正常 |
| 兴奋 | 黄色，快速脉动 | 眼睛睁大，微笑 | 前倾，跳跃 | 大量粒子，快速环绕 | 加快 |
| 愤怒 | 红色，剧烈脉动 | 皱眉，咬牙 | 紧绷，攻击性姿态 | 火焰状粒子，向外喷射 | 极快 |
| 悲伤 | 紫色，微弱脉动 | 流泪，嘴角下垂 | 低垂，蜷缩 | 雨滴状粒子，向下飘落 | 减慢 |
| 恐惧 | 白色，闪烁 | 眼睛圆睁，嘴巴张开 | 退缩，颤抖 | 散射状粒子，向外逃离 | 颤抖 |
| 好奇 | 青色，规律脉动 | 眼睛闪烁，歪头 | 前倾，观察 | 问号状粒子，围绕目标 | 正常偏快 |
| 友善 | 粉色，温暖脉动 | 微笑，眼睛弯弯 | 开放，靠近 | 心形粒子，缓慢飘散 | 正常 |
| 敌意 | 暗红色，不稳定脉动 | 瞪眼，龇牙 | 紧绷，对峙 | 尖刺状粒子，围绕身体 | 加快 |

**设计要点：**
- 情绪变化是渐变的，不是瞬间切换（从平静到愤怒需要2-3秒过渡）
- 情绪强度影响表现程度（轻微愤怒vs极度愤怒有明显差异）
- 情绪的视觉表现需要在"俯视角RTS"中也能清晰识别（核心颜色是最主要的识别通道）

### 2.5 灵魂的动画系统

| 动画类型 | 帧数 | 说明 |
|----------|------|------|
| 待机 | 4帧循环 | 呼吸/轻微晃动，体现"活着"的感觉 |
| 行走 | 6帧循环 | 8方向（4方向+镜像），移动时播放 |
| 攻击 | 4帧 | 攻击前摇+攻击+后摇，不同技能有不同动画 |
| 受击 | 2帧 | 受击闪烁+后退，短暂无敌时间 |
| 击败 | 6帧 | 能量核心熄灭+外壳消散+粒子爆发 |
| 互动 | 4帧 | 与交互物体/其他灵魂互动时播放 |
| 表情 | 2帧/表情 | 眼睛/嘴巴的变化，叠加在基础动画上 |
| 技能特效 | 8-16帧 | 技能释放时的特效动画（火焰/冰霜/雷电等） |

**动画原则：**
- 像素风阶段：精简帧数，确保流畅度优先（待机4帧、行走6帧即可）
- 手绘风阶段：增加帧数，提升表现力（待机8帧、行走12帧）
- 动画风格统一：所有灵魂使用相同的动画骨架和节奏，确保视觉一致性

## 三、世界视觉设计

### 3.1 场景视觉风格

**阶段一（RTS对战）：俯视角2D像素场景**

| 场景类型 | 视觉特征 | 色彩基调 |
|----------|----------|----------|
| 经典竞技场 | 石质地面，圆形竞技场，四周观众席（装饰） | 灰/棕/暖黄 |
| 迷雾森林 | 茂密树木，雾气效果，隐藏路径，发光蘑菇 | 深绿/紫/蓝 |
| 熔岩洞穴 | 岩石地面，熔岩流动，火光闪烁，炙热空气效果 | 红/橙/黑 |
| 天空之桥 | 云朵平台，彩虹桥，浮空岛屿，蓝天背景 | 蓝/白/粉 |
| 资源孤岛 | 海洋环绕，沙滩，棕榈树，宝藏 | 青/绿/金 |
| 镜像迷宫 | 石质迷宫，对称设计，火把照明，回声效果 | 灰/橙/深蓝 |
| 极地冰原 | 雪地，冰山，极光，结冰湖面 | 白/蓝/紫 |
| 废弃工厂 | 金属地面，齿轮，管道，蒸汽，机械装置 | 灰/铜/暗绿 |

**场景视觉层次：**
- **背景层**：远景（山脉/天空/洞穴墙壁），视差滚动
- **装饰层**：中景装饰（树木/岩石/建筑），不影响移动
- **地面层**：可移动区域，不同地形有不同视觉表现
- **实体层**：灵魂/交互物体/资源点，可交互
- **特效层**：粒子/光效/天气效果，叠加在最上层

### 3.2 环境效果与氛围

| 效果类型 | 说明 | 技术实现 |
|----------|------|----------|
| 光照 | 动态光源（火把/魔法光球）照亮周围区域，阴影投射 | Seed LightSystem + 2D光照渲染 |
| 热力 | 热源区域有空气扭曲效果，冷源区域有雾气效果 | Seed ThermalSystem + 粒子特效 |
| 声学可视化 | 灵魂发出声音时有波纹扩散，墙体阻挡波纹 | Seed AcousticPropagation + 波纹动画 |
| 天气 | 雨/雪/雾/风等天气效果，影响视野和移动 | 粒子系统 + 后期处理 |
| 时间 | 昼夜循环，影响光照和灵魂行为（昼夜节律子系统） | 时间系统 + 光照变化 |
| 粒子 | 各种环境粒子（落叶/火花/气泡/尘埃） | 粒子系统 |
| 屏幕震动 | 爆炸/重击时的屏幕震动效果 | 相机震动 |
| 慢放特效 | 名场面时的慢放+特写 | 时间缩放 + 相机聚焦 |

### 3.3 地图视觉设计原则

1. **可读性优先** — 玩家必须能快速识别灵魂位置、资源点、危险区域、掩体
2. **对比度控制** — 灵魂角色与背景的对比度足够高，确保在复杂场景中清晰可见
3. **信息分层** — 重要信息（灵魂/资源点）在视觉上突出，次要信息（装饰/背景）弱化
4. **方向感** — 地图设计要有清晰的方向感（中央/边缘/我方/敌方），避免玩家迷路
5. **美观性** — 在保证可读性的前提下，追求视觉美感和氛围营造

## 四、UI/UX设计方向

### 4.1 UI设计原则

| 原则 | 说明 |
|------|------|
| 简洁清晰 | UI元素不遮挡游戏内容，信息层级分明 |
| 风格统一 | 所有UI使用统一的设计语言（像素风/圆角/配色） |
| 响应迅速 | UI交互有即时反馈（点击/悬停/切换都有动画） |
| 可定制 | 玩家可以调整UI布局、大小、透明度 |
| 无障碍 | 支持色盲模式、字体大小调整、高对比度模式 |

**对战界面设计要点：**
- 游戏画面占屏幕80%以上，UI元素不遮挡核心战斗区域

- 指令按钮大而清晰，支持快捷键
- 小地图显示灵魂位置、资源点、危险区域
- 内心独白以气泡形式出现在灵魂上方，不遮挡战斗

### 4.3 UX设计要点

**新手引导：**
- 渐进式引导——不是一次性教程，而是在玩家需要时弹出提示
- 引导可以跳过，老玩家直接进入游戏
- 关键操作有高亮提示和动画演示

**反馈设计：**
- 所有操作都有即时反馈（视觉+听觉）
- 成功操作有正向反馈（特效+音效+满足感）
- 失败操作有解释性反馈（为什么失败+如何改进）

**信息层级：**
- 一级信息（当前最重要的）：大字体+高对比度+突出位置
- 二级信息（次要的）：中等字体+正常对比度
- 三级信息（详细的）：小字体+低对比度+可展开

**移动端适配（阶段二）：**
- 竖屏设计为主，横屏为可选
- 大按钮（最小48×48像素），适合触控
- 简化UI层级，减少深层菜单
- 支持手势操作（滑动/捏合/长按）

**选择Godot的核心理由：**
1. **2D像素风的最佳选择** — Godot的2D渲染是所有引擎中最优秀的，像素风游戏性能极佳
2. **小团队友好** — 1-3人团队可以快速上手，GDScript学习成本低
3. **开源免费无分成** — 不需要支付授权费或收入分成，利润全部归团队
4. **全平台导出** — 一次开发，导出Steam（PC）、移动端、Web端
5. **与现有后端兼容** — 通过HTTP/WebSocket与SoulArena/Seed/Superbase通信，技术栈兼容
6. **社区增长快** — Godot 4.x发布后社区活跃度大幅提升，资源和教程越来越多

### 5.4 网络同步方案

**RTS对战的网络同步：**

| 方案 | 说明 | 选择 |
|------|------|------|
| 帧同步 | 所有客户端同步执行相同的游戏逻辑，只传输玩家输入 | ❌ 不适用（灵魂是自主决策的，不是玩家输入驱动的） |
| 状态同步 | 服务器运行权威游戏逻辑，定期同步状态到客户端 | ✅ 选择（服务器运行SoulArena+Seed，客户端只做渲染和输入） |
| 预测回滚 | 客户端预测+服务器纠正 | 🟡 可选（用于减少延迟感，但复杂度高，阶段一不做） |

**状态同步的具体方案：**
- 游戏逻辑完全运行在服务器端（SoulArena + Seed + 游戏规则层）
- 服务器每100ms（10tick/s）向客户端同步一次游戏状态
- 客户端做插值平滑（在两个状态包之间插值，确保流畅）
- 玩家指令（集合/撤退/攻击目标）通过WebSocket实时发送到服务器
- 延迟<200ms时体验流畅，超过200ms时显示延迟提示

**为什么选择状态同步：**
- 灵魂是自主决策的，游戏逻辑在服务器端运行，客户端只做渲染
- 状态同步天然支持观战（任何客户端都可以连接到服务器观看对战）
- 防作弊（游戏逻辑在服务器端，客户端无法修改）
- 与现有架构兼容（SoulArena和Seed本来就是服务端运行的）

## 六、动画与特效设计

### 6.1 动画风格

**像素风阶段：**
- 简洁明快的像素动画，帧数精简但流畅
- 重点动画（攻击/受击/击败）多几帧，次要动画（行走/待机）少几帧
- 动画风格参考：《星露谷物语》《挺进地牢》《以撒的结合》

**手绘风阶段（升级后）：**
- 流畅细腻的手绘动画，帧数充足
- 灵魂的表情和动作更丰富，情绪传达更细腻
- 动画风格参考：《空洞骑士》《奥日与黑暗森林》《哈迪斯》

### 6.2 特效设计

| 特效类型 | 说明 | 示例 |
|----------|------|------|
| 技能特效 | 技能释放时的视觉效果 | 火焰冲击=橙色粒子+冲击波；冰霜箭=蓝色冰晶+拖尾 |
| 受击特效 | 灵魂受到攻击时的效果 | 受击闪烁+粒子飞溅+屏幕轻微震动 |
| 击败特效 | 灵魂被击败时的效果 | 能量核心熄灭+外壳碎裂+粒子爆发+慢放 |
| 环境特效 | 地图中的环境效果 | 熔岩冒泡+热浪扭曲；火把闪烁+光照变化；雾气流动 |
| UI特效 | UI交互的视觉反馈 | 按钮悬停发光+点击缩放；奖励弹出+粒子；升级光效 |
| 名场面特效 | 名场面发生时的特殊效果 | 慢放+特写+屏幕边框光效+回放提示 |

**特效设计原则：**
- 特效不能遮挡游戏内容（透明度控制+层级管理）
- 特效性能优化（粒子数量限制+对象池+LOD）
- 不同技能的特效有明显区分度（颜色+形状+运动模式）
- 特效与灵魂个性关联（勇敢的灵魂攻击特效更猛烈，谨慎的灵魂更柔和）

**音效设计原则：**

- 支持音量调节（音乐/音效/语音分别调节）
- 支持无障碍（字幕+视觉提示替代重要音效）
