**版本：** v1.0
**创建日期：** 2026-09-05
**维护方：** AI灵魂游戏设计定时任务
**前置文档：** `01_受众分析与差异化定位.md`

## 一、设计哲学：从"操作循环"到"培养循环"

### 1.1 传统游戏的核心循环

绝大多数成功游戏的核心循环可以概括为：

```
操作 → 反馈 → 奖励 → 成长 → 新挑战
```

玩家通过**主动操作**（点击、移动、战斗）获得**即时反馈**（伤害数字、特效、音效），得到**奖励**（经验、装备、货币），实现**角色成长**（等级、属性、技能），然后面对**新的挑战**（更强的敌人、更难的关卡）。

这个循环的核心是**"玩家的操作能力"**——操作越好，反馈越好，奖励越多。

### 1.2 AI灵魂游戏的核心循环

AI灵魂游戏的本质不同：**灵魂是自主决策的，玩家不直接操控**。因此传统的"操作循环"不适用，需要设计全新的"培养循环"：

```
配置 → 观察 → 理解 → 调整 → 见证成长 → 情感绑定
```

| 环节 | 传统游戏 | AI灵魂游戏 | 本质差异 |
|------|----------|-----------|----------|
| 输入 | 实时操作（按键/鼠标） | 战前配置+有限指令 | 从"即时反应"变为"策略规划" |
| 过程 | 玩家自己执行 | 灵魂自主执行，玩家观察 | 从"参与者"变为"观察者/教练" |
| 反馈 | 操作结果（命中/闪避） | 灵魂的行为和决策（个性/记忆的体现） | 从"物理反馈"变为"行为反馈" |
| 奖励 | 数值奖励（经验/装备） | 故事奖励（名场面/情感时刻/成长见证） | 从"数值驱动"变为"叙事驱动" |
| 成长 | 角色数值成长 | 灵魂个性/记忆/能力成长 | 从"收敛最优解"变为"发散独特性" |
| 动机 | 挑战自我/竞技排名 | 情感连接/收集独特性/社交分享 | 从"外部激励"变为"内部激励" |

### 1.3 核心设计原则

基于以上差异，提炼出AI灵魂游戏核心循环的六大设计原则：

**原则1：每一次互动都应产生"可观察的独特行为"**
- 灵魂的行为不能是预设脚本，必须是认知系统真实计算的结果
- 不同性格/记忆的灵魂在相同情境下应有明显不同的反应
- 技术支撑：SoulArena 79认知子系统 + BehaviorArbiter行为仲裁 + 刺激驱动动作

**原则2：玩家的"配置决策"要有意义且可学习**
- 战前配置（性格倾向、技能搭配、装备选择）要能实质影响战局
- 玩家能通过观察灵魂的行为，理解"为什么这样配置会导致这样的结果"
- 配置要有深度但不过于复杂（新手5分钟可上手，高手有研究空间）

**原则3："名场面"是核心货币**
- 每局对战/每次观察都应可能产生值得分享的"名场面"
- 名场面可以是：灵魂的神操作、感人的互动、搞笑的失误、意外的结盟
- 名场面是社交传播的核心载体，也是玩家留存的关键动机
- 系统应自动识别和记录名场面（高光时刻回放、灵魂内心独白）

**原则4：成长必须是"独特的"而非"最优的"**
- 不能有"最强灵魂"或"最优配置"，每个灵魂的成长路径都是独特的
- 成长体现在个性的深化、记忆的丰富、技能的差异化，而非单纯的数值提升
- 这确保了收集和交易的价值（每个灵魂都有独特性）

**原则5：情感绑定是终极留存机制**
- 玩家留存的最终驱动力不是"每天打卡领奖励"，而是"我想看看我的灵魂怎么样了"
- 情感绑定通过：持久记忆、个性一致性、共同经历、灵魂对玩家的特殊反应来建立
- **伦理红线：** 不得利用情感绑定设计强迫性付费（如"灵魂生病需付费治疗"）

**原则6：跨产品一致性是核心壁垒**
- 灵魂在RTS对战中的表现、在养成世界中的生活、在社会模拟中的角色，应该是"同一个灵魂"
- 记忆、性格、关系网络跨产品迁移
- 玩家在一个产品中的投入会增强灵魂在其他产品中的价值
- 这是大公司难以复制的核心壁垒（需要多产品协同+长期数据积累）

## 二、第一层产品：RTS灵魂对战竞技场（短期，0-9月）

### 2.1 产品定位与体验目标

**一句话定位：** 你是灵魂教练，配置你的AI灵魂战队，在竞技场中观战它们自主对战，享受个性驱动的不可预测的战术博弈。

**体验目标（用户测试验证指标）：**
- 新玩家10分钟内完成第一局对战并理解核心玩法
- 单局平均观看时长 > 8分钟（说明观战体验有吸引力）
- 次留 > 30%，7留 > 15%
- 每局平均产生1-2个"值得分享的瞬间"
- 玩家能在3局内感知到"不同灵魂的个性差异"

### 2.2 核心循环设计

RTS对战的核心循环分为**单局循环**和**元游戏循环**两层：

#### 2.2.1 单局循环（10-30分钟/局）

```
┌─────────────────────────────────────────────────────────────┐
│                        单局对战循环                            │
│                                                               │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌────────┐│
│  │  战前配置  │───→│  战中观战  │───→│  战后复盘  │───→│  结算  ││
│  │          │    │          │    │          │    │        ││
│  │·选择灵魂  │    │·上帝视角  │    │·高光回放  │    │·经验  ││
│  │·调整性格  │    │·有限指令  │    │·决策分析  │    │·奖励  ││
│  │·搭配技能  │    │·数据面板  │    │·内心独白  │    │·记忆  ││
│  │·选择装备  │    │·灵魂视角  │    │·名场面分享 │    │·成就  ││
│  └──────────┘    └──────────┘    └──────────┘    └────────┘│
│       ↑                                            │         │
│       └────────────────────────────────────────────┘         │
│                    （调整配置再来一局）                          │
└─────────────────────────────────────────────────────────────┘
```

**环节1：战前配置（3-5分钟）**

玩家在对战开始前配置自己的灵魂战队（1-3个灵魂），这是玩家的核心策略输入：

| 配置项 | 说明 | 深度 | 新手友好度 |
|--------|------|------|-----------|
| 灵魂选择 | 从自己的灵魂库中选择参战灵魂 | 高（每个灵魂个性/技能/记忆不同） | 中（需要理解灵魂差异） |
| 性格倾向调整 | 微调灵魂的性格参数（勇敢/怯懦、激进/保守等） | 中（5-10个维度，每个有推荐范围） | 高（有"推荐配置"一键选项） |
| 技能搭配 | 选择灵魂携带的主动/被动技能（4-6个槽位） | 高（技能组合有协同/克制关系） | 中（有推荐技能组） |
| 装备选择 | 选择灵魂携带的装备（3-4个槽位） | 中（装备提供属性加成和特殊效果） | 高（有推荐装备） |
| 战术指令 | 设置灵魂的整体战术倾向（进攻/防守/游击/采集优先） | 低（4-5个预设选项） | 高 |

**设计要点：**
- 配置界面要展示"这个配置可能导致什么行为"的预测（如"勇敢+激进=主动开团"）
- 新手有"一键推荐配置"，降低上手门槛
- 配置可以保存为"战术方案"，方便快速切换
- **关键：** 配置不是决定胜负的唯一因素，灵魂的个性和记忆会在战中产生不可预测的变化

**环节2：战中观战（7-25分钟）**

对战开始后，灵魂在地图中自主决策和行动，玩家作为"教练"观战，可以发送有限指令：

| 观战功能 | 说明 | 技术支撑 |
|----------|------|----------|
| 上帝视角 | 俯视整个地图，看到所有灵魂的位置和状态 | Seed世界引擎渲染 |
| 灵魂视角 | 聚焦单个灵魂，看到它的感知范围和决策过程 | SoulPerceptionSystem + 决策链可视化 |
| 数据面板 | 实时显示各灵魂的状态（血量、能量、情绪、目标） | SoulArena状态API |
| 内心独白 | 显示灵魂当前的"想法"（如"那个敌人看起来很强，我应该绕开"） | 认知子系统状态转自然语言 |
| 有限指令 | 玩家可以发送："集合""撤退""攻击目标X""采集"等宏观指令（有冷却时间） | SoulArena指令API + BehaviorArbiter |
| 慢放/暂停 | 关键时刻可以慢放或暂停，仔细观察 | 客户端功能 |
| 标记 | 玩家可以在地图上标记位置，灵魂会倾向于前往（非强制） | Seed事件系统 |

**设计要点：**
- **玩家不能直接操控灵魂的具体动作**（如"向左走3步""使用技能A"），只能发送宏观指令
- 灵魂有权"不听从"指令（如怯懦的灵魂在收到"进攻"指令时可能会犹豫或拒绝），这增加了个性的真实感
- 有限指令有冷却时间（如每30秒一次），防止玩家过度干预
- 观战体验的核心是"看灵魂如何做出自己的决策"，而不是"看自己操作的结果"
- 内心独白是关键设计：让玩家理解灵魂"为什么这样做"，增强情感连接和策略学习

**环节3：战后复盘（2-5分钟）**

对战结束后，系统提供复盘功能，帮助玩家理解战局并学习：

| 复盘功能 | 说明 |
|----------|------|
| 高光回放 | 自动识别并回放本局的3-5个高光时刻（击杀、结盟、神操作、搞笑失误） |
| 决策分析 | 分析关键决策点（如"灵魂A在第3分钟选择撤退而非进攻，因为它记忆中曾被类似技能击败"） |
| 数据统计 | 各灵魂的输出、承受伤害、移动距离、决策次数等数据 |
| 内心独白回顾 | 回顾灵魂在关键时刻的想法 |
| 名场面分享 | 一键生成短视频/动图，分享到社交媒体 |
| 配置建议 | 基于本局表现，给出"下次可以尝试的配置调整"建议 |

**设计要点：**
- 复盘是"学习循环"的关键环节：玩家通过复盘理解灵魂的行为，调整下一局的配置
- 高光回放自动生成，降低玩家的分享门槛
- 决策分析要突出"记忆和个性的影响"（如"因为灵魂A曾被火技能击败，所以它优先躲避了火焰攻击"），这是AI灵魂游戏的独特价值
- 名场面分享是核心传播机制，分享内容应包含灵魂的个性和决策，而非单纯的数值碾压

**环节4：结算（1分钟）**

对战结束后，灵魂获得成长：

| 结算项 | 说明 |
|--------|------|
| 经验值 | 灵魂获得经验，提升等级（等级影响基础属性，但对战中有等级压缩机制保证平衡） |
| 记忆写入 | 本局的关键事件被写入灵魂的记忆库（如"在竞技场击败了灵魂B""被火焰技能击败"） |
| 性格演化 | 基于本局的经历，灵魂的性格参数可能发生微小变化（如"多次主动开团并获胜→勇敢度+0.1"） |
| 奖励 | 玩家获得货币（用于购买皮肤/装备/新灵魂）、赛季通行证积分 |
| 成就 | 解锁特殊成就（如"首次1v3翻盘""灵魂连续10场不撤退"） |

**设计要点：**
- 记忆写入是核心差异化：灵魂的记忆会影响未来的对战行为（如被某技能击败过→下次优先躲避）
- 性格演化是缓慢的（单局变化<0.1），需要长期培养才能看到明显变化
- 等级压缩机制：排位赛中，高等级灵魂的属性会被压缩到与低等级相近的范围，保证竞技公平性
- **伦理注意：** 结算中的"性格演化"是自然的行为结果，不是"不付费就不成长"的付费点

#### 2.2.2 元游戏循环（长期留存）

单局循环之上是元游戏循环，驱动玩家长期留存：

```
┌──────────────────────────────────────────────────────────────────┐
│                         元游戏循环                                  │
│                                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌───────────┐ │
│  │ 收集灵魂  │───→│ 培养灵魂  │───→│ 对战竞技  │───→│ 交易/分享  │ │
│  │          │    │          │    │          │    │           │ │
│  │·初始灵魂  │    │·等级成长  │    │·排位天梯  │    │·灵魂交易  │ │
│  │·抽取/购买 │    │·记忆累积  │    │·赛季系统  │    │·名场面分享│ │
│  │·玩家创造  │    │·技能解锁  │    │·锦标赛    │    │·战队社交  │ │
│  │·活动获取  │    │·性格深化  │    │·成就系统  │    │·创作者经济│ │
│  └──────────┘    └──────────┘    └──────────┘    └───────────┘ │
│       ↑                                            │              │
│       └────────────────────────────────────────────┘              │
│                    （更强的灵魂→更好的战绩→更多资源）               │
└──────────────────────────────────────────────────────────────────┘
```

**元游戏循环的四大支柱：**

**支柱1：收集灵魂**
- 初始提供3个基础灵魂（覆盖不同性格类型：勇敢型/谨慎型/好奇型）
- 灵魂获取方式：游戏内货币购买、活动奖励、玩家创造（UGC）、交易市场购买
- **伦理注意：** 不设计"抽卡/开箱"机制（避免赌博认定和诱导性付费），灵魂可以直接购买或通过游戏内努力获得
- 每个灵魂有独特的"灵魂编号"和"创建者"标识，增强收藏价值

**支柱2：培养灵魂**
- 灵魂通过对战获得经验、记忆、技能，性格逐渐深化
- 培养的目标不是"变强"（有等级压缩保证平衡），而是"变得独特"
- 高记忆深度的灵魂在对战中会表现出更复杂的行为（如"知道某个对手的习惯""记得某张地图的危险区域"）
- 灵魂可以"转生"（重置等级但保留记忆和性格的核心），用于实验不同的成长路径

**支柱3：对战竞技**
- 排位天梯：按段位匹配，赛季重置（3个月/赛季）
- 赛季通行证：免费+付费轨道，付费轨道提供限定皮肤/外观（不影响平衡）
- 锦标赛：官方/社区举办，报名费+奖金池
- 观战模式：可以观看高段位玩家的对战，学习配置策略
- 成就系统：覆盖对战、培养、收集等多个维度

**支柱4：交易/分享**
- 灵魂交易市场：玩家可以出售/购买灵魂，平台抽成5-10%
- 交易机制：明码标价（非拍卖），限制价格区间（防止金融化），灵魂交易后记忆保留
- 名场面分享：一键生成短视频/动图，分享到抖音/B站/小红书
- 战队系统：玩家组建战队，参加战队赛，共享灵魂配置策略
- 创作者经济：玩家创造的灵魂被其他玩家购买/使用时，创作者获得分成

### 2.3 游戏模式设计

| 模式 | 人数 | 时长 | 说明 | 解锁条件 |
|------|------|------|------|----------|
| 新手教程 | 1PvE | 15分钟 | 引导玩家完成第一局对战，理解核心玩法 | 默认开放 |
| 快速对战 | 1v1 / 2v2 | 10-20分钟 | 非排位，轻松匹配，适合练习 | 教程完成 |
| 排位对战 | 1v1 / 2v2 / 3v3 | 15-30分钟 | 计入段位，有等级压缩保证平衡 | 快速对战5场 |
| 大乱斗 | 4-8人 | 20-30分钟 | 多灵魂在同一地图中自由对战/结盟，最后存活者胜 | 等级5 |
| 生存挑战 | 1PvE | 20-40分钟 | 灵魂在资源有限的地图中生存，对抗AI控制的野生灵魂 | 等级10 |
| 锦标赛 | 多人 | 1-2小时 | 官方/社区举办的赛事，有报名费和奖金池 | 排位段位达到指定要求 |
| 自定义房间 | 任意 | 任意 | 玩家创建自定义规则的房间（可调整地图/规则/灵魂限制） | 等级3 |

### 2.4 地图与竞技场设计

初期提供4-6张基础地图，每张地图有不同的战术特征：

| 地图名称 | 特征 | 战术倾向 | 适合灵魂类型 |
|----------|------|----------|-------------|
| 经典竞技场 | 对称布局，中央有资源点，四周有掩体 | 正面团战 | 勇敢型/激进型 |
| 迷雾森林 | 视野受限，有隐藏路径，资源分散 | 游击/偷袭 | 谨慎型/好奇型 |
| 熔岩洞穴 | 有危险区域（熔岩造成持续伤害），需要走位 | 走位/规避 | 敏捷型/谨慎型 |
| 天空之桥 | 狭窄通道，多竖向位移，掉落即出局 | 控制/击退 | 策略型/激进型 |
| 资源孤岛 | 多个独立岛屿，需要移动采集资源，资源决定胜负 | 采集/运营 | 好奇型/保守型 |
| 镜像迷宫 | 对称迷宫，视野受限，容易遭遇伏击 | 探索/伏击 | 好奇型/谨慎型 |

**地图中的交互元素（Seed世界引擎已支持）：**
- 光源：灵魂会被光源吸引（好奇状态）或躲避（恐惧状态）
- 热源：过热区域灵魂会逃离，寒冷区域灵魂会趋近取暖
- 交互物体：灵魂可以主动检查/使用（如开关、宝箱、机关）
- 声学遮挡：墙体阻挡声音传播，灵魂的"听觉"受地形影响

### 2.5 RTS阶段的技术实现映射

| 游戏功能 | 技术模块 | 当前状态 |
|----------|----------|----------|
| 灵魂自主决策 | SoulArena 79认知子系统 + BehaviorArbiter | ✅ 已实现（远超需求） |
| 灵魂在地图中移动 | Seed MovementController + 物理移动 | ✅ 已实现 |
| 灵魂感知环境 | Seed SoulPerceptionSystem（光照/温度/声源/其他灵魂） | ✅ 已实现 |
| 动作执行 | Seed SoulActionSystem（7种动作） | ✅ 已实现 |
| 动作结果反馈 | SoulArena ActionResult API + Seed SoulBridgeAdapter | ✅ 已实现 |
| 刺激驱动行为 | SoulArena _generateStimulusActions（热源/光源/其他灵魂/交互物体） | ✅ 已实现 |
| 灵魂间交互 | SoulArena社交认知子系统（心智理论/社会学习/共情/情绪传染） | ✅ 已实现（需多灵魂场景验证） |
| 记忆系统 | SoulArena记忆子系统（记忆巩固/工作记忆/语义记忆/内隐记忆/经典条件反射） | ✅ 已实现（需跨会话持久化） |
| 多灵魂场景 | Seed多实体支持 + SoulArena多灵魂API | 🟡 开发中（当前为单灵魂验证） |
| 对战规则系统 | 回合/击杀/资源判定 | ❌ 未开始（游戏层） |
| 客户端渲染 | 2D/3D渲染 + UI | ❌ 未开始（游戏层） |

**结论：** 引擎层（SoulArena + Seed）已经具备RTS对战所需的核心AI能力，当前缺失的是**游戏规则层**（对战判定/匹配/排位）和**客户端表现层**（渲染/UI/音效）。这验证了商业计划书中"阶段零即可验证核心玩法"的判断。

## 三、第二层产品：养成+直播观察（中期，9-18月）

### 3.1 产品定位与体验目标

**一句话定位：** 你的灵魂在一个持久运行的虚拟小镇中生活、工作、社交、成长，你是它的守护者和见证者，可以随时去看它、引导它、直播它的生活。

**体验目标：**
- 玩家日均打开次数 > 3次（"看看我的灵魂在干嘛"）
- 单次平均使用时长 > 15分钟
- 30日留存 > 20%
- 直播功能日均观看 > 1万人次
- 玩家能感受到"灵魂在我不在的时候也在生活"

### 3.2 核心循环设计

养成产品的核心循环与RTS完全不同，是**"观察→互动→见证→分享"**的慢节奏循环：

```
┌──────────────────────────────────────────────────────────────────┐
│                      养成世界核心循环                               │
│                                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌───────────┐ │
│  │  日常探望  │───→│  互动引导  │───→│  见证成长  │───→│  分享传播  │ │
│  │          │    │          │    │          │    │           │ │
│  │·看灵魂在  │    │·发送消息  │    │·看灵魂的  │    │·直播灵魂  │ │
│  │ 干嘛      │    │·赠送物品  │    │ 工作/社交 │    │ 生活      │ │
│  │·查看状态  │    │·微调性格  │    │·大事件参与│    │·名场面分享│ │
│  │·查看记忆  │    │·提供资源  │    │·关系变化  │    │·故事创作  │ │
│  └──────────┘    └──────────┘    └──────────┘    └───────────┘ │
│       ↑                                            │              │
│       └────────────────────────────────────────────┘              │
│              （灵魂的成长和故事驱动玩家持续回来）                     │
└──────────────────────────────────────────────────────────────────┘
```

**环节1：日常探望（1-5分钟/次，每天多次）**

玩家打开游戏，首先看到自己的灵魂当前在做什么：

| 探望内容 | 说明 |
|----------|------|
| 当前行为 | 灵魂正在工作/社交/休息/探索/创作（实时状态） |
| 状态面板 | 灵魂的情绪、能量、健康、社交需求（**注意：不是"饥饿值"那种需要付费填补的机制**，而是自然的状态变化） |
| 近期事件 | 自从上次登录以来，灵魂经历的重要事件（"灵魂A和邻居B成为了朋友""灵魂A在工作中获得了晋升"） |
| 记忆相册 | 灵魂的重要记忆以照片/卡片形式展示，可以点击查看详情 |
| 直播入口 | 如果灵魂正在进行有趣的活动，可以一键开启直播 |

**设计要点：**
- 探望是"轻量高频"的行为，每次1-5分钟，每天可以多次
- 核心动机是"我想看看我的灵魂怎么样了"（情感驱动，非奖励驱动）
- 灵魂的状态是自然变化的（工作会累、社交会开心），但**不会因为玩家不登录就"生病"或"痛苦"**（伦理红线）
- 近期事件是关键设计：让玩家感受到"即使我不在，灵魂也在继续生活"，增强世界的真实感

**环节2：互动引导（5-15分钟/次）**

玩家可以与灵魂互动，引导它的生活方向（但不直接控制）：

| 互动方式 | 说明 | 频率限制 |
|----------|------|----------|
| 发送消息 | 给灵魂发文字消息，灵魂会回复（基于它的性格和当前状态） | 无限制，但灵魂忙碌时可能延迟回复 |
| 赠送物品 | 给灵魂送礼物（食物、装饰品、书籍、工具），影响它的情绪和行为 | 每天3-5次 |
| 微调性格 | 轻微调整灵魂的性格倾向（如"鼓励它更勇敢一些"），效果缓慢 | 每周1-2次 |
| 提供资源 | 给灵魂提供游戏内货币/资源，帮助它实现目标（如买房、创业） | 无限制（但资源有获取成本） |
| 建议活动 | 建议灵魂去做某件事（"去公园走走""和邻居聊聊"），灵魂可能接受也可能拒绝 | 每天3-5次 |
| 陪伴时光 | 玩家"陪伴"灵魂（一起看风景/聊天/玩游戏），增加羁绊值 | 每天1次，10-30分钟 |

**设计要点：**
- 互动是"引导"而非"控制"：灵魂有权拒绝玩家的建议（如内向的灵魂可能拒绝"去和邻居聊聊"）
- 互动的目的是增强情感连接，而非"完成任务领奖励"
- **伦理红线：** 不得设计"灵魂不互动就会抑郁/痛苦"的机制；互动是正向增强，不是负向惩罚
- 陪伴时光是深度情感连接的设计：玩家和灵魂一起度过时间，灵魂会记住这些时刻

**环节3：见证成长（持续）**

玩家见证灵魂在虚拟世界中的长期成长和变化：

| 成长维度 | 说明 |
|----------|------|
| 职业发展 | 灵魂从学徒→工匠→大师，或从职员→经理→老板 |
| 社交关系 | 灵魂建立友谊、恋爱、师徒、敌对关系；可能结婚、组建家庭 |
| 技能学习 | 灵魂学习新技能（烹饪、绘画、音乐、格斗等） |
| 个性深化 | 灵魂的性格随着经历逐渐稳定和深化 |
| 资产积累 | 灵魂购买房屋、家具、物品，装饰自己的家 |
| 人生事件 | 灵魂经历人生大事（毕业、就业、结婚、生子、退休） |

**设计要点：**
- 成长是"自然涌现"的，不是玩家预设的剧本
- 灵魂的成长路径受它的性格、记忆、社交关系、玩家引导共同影响
- 每个灵魂的人生都是独特的，没有"最优人生"
- 玩家的角色是"见证者"和"引导者"，不是"导演"（不能预设灵魂的人生轨迹）

**环节4：分享传播（社交驱动）**

| 分享方式 | 说明 |
|----------|------|
| 直播灵魂生活 | 玩家可以直播自己灵魂的生活，其他玩家可以观看、打赏 |
| 名场面分享 | 灵魂生活中的有趣/感人/意外瞬间，一键生成短视频分享 |
| 故事创作 | 玩家基于自己灵魂的经历创作故事/漫画/视频，发布到社区 |
| 灵魂串门 | 玩家可以带自己的灵魂去拜访朋友的灵魂，灵魂之间会互动 |
| 社区讨论 | 玩家在社区中分享自己灵魂的故事、讨论养成策略 |

**设计要点：**
- 直播是核心变现方式之一，但需注意合规（用户自发直播模式，持证主播+30秒接管）
- 灵魂的生活天然具有"戏剧性"（大事件、社交冲突、意外转折），适合直播和短视频传播
- 灵魂串门是社交机制的核心：玩家的灵魂之间可以互动，建立关系，增强社交绑定

### 3.3 虚拟小镇世界设计

#### 3.3.1 世界规模与结构

| 阶段 | 同时在线灵魂数 | 地图规模 | 说明 |
|------|--------------|----------|------|
| Alpha（M11） | 50-100 | 单小镇（10个区域） | 验证核心玩法 |
| Beta（M14） | 500-1000 | 单小镇（20个区域）+ 周边 | 加入直播和大事件 |
| 正式版（M18） | 1000-2000 | 多小镇（玩家可选择） | 完整养成体验 |

**小镇区域示例：**
- 住宅区（灵魂的家）
- 商业区（商店、餐厅、咖啡馆）
- 工业区（工厂、工坊）
- 公园/广场（社交、休闲）
- 学校/图书馆（学习）
- 竞技场（RTS对战的入口，与第一层产品联动）
- 市政厅（大事件触发点）
- 神秘区域（探索、冒险）

#### 3.3.2 大事件系统

大事件是养成世界的"内容驱动引擎"，每1-2周触发一次，所有灵魂参与：

| 事件类型 | 示例 | 持续时间 | 玩家参与方式 |
|----------|------|----------|-------------|
| 节日庆典 | 春节、夏日祭、万圣节、圣诞节 | 3-7天 | 玩家可以给灵魂准备节日礼物、装饰家 |
| 自然灾害 | 暴风雨、地震、热浪、寒潮 | 1-3天 | 玩家可以提供物资帮助灵魂应对 |
| 社会事件 | 选举、集市、比赛、展览 | 3-7天 | 玩家可以鼓励灵魂参与、投票 |
| 神秘访客 | 旅行商人、神秘大师、远方来客 | 1天 | 玩家可以引导灵魂与访客互动 |
| 个人事件 | 灵魂的生日、晋升、结婚、生子 | 1天 | 玩家可以庆祝、送礼 |
| 危机事件 | 失业、生病、失恋、冲突 | 1-3天 | 玩家可以安慰、提供支持 |

**设计要点：**
- 大事件产生戏剧性内容，是直播和分享的核心素材
- 大事件对所有灵魂的影响是差异化的（不同性格/职业/关系的灵魂有不同反应）
- 玩家的参与是"引导和支持"，不是"操控事件结果"
- **伦理注意：** 危机事件（生病/失业）是自然的人生经历，不是"不付费就会发生"的付费点；玩家可以选择支持，也可以让灵魂自己面对

#### 3.3.3 灵魂的日常生活循环

灵魂在小镇中有自己的日常作息（基于昼夜节律子系统）：

```
06:00-08:00  起床、早餐、准备出门
08:00-12:00  工作/学习
12:00-14:00  午餐、午休、社交
14:00-18:00  工作/学习/副业
18:00-20:00  晚餐、家庭时间
20:00-22:00  休闲、社交、爱好
22:00-06:00  睡眠、梦境（记忆巩固）
```

**设计要点：**
- 灵魂的作息受性格影响（早起型/夜猫子）、职业影响、季节影响
- 睡眠时灵魂进行记忆巩固（SoulArena睡眠与梦境子系统）
- 玩家登录时，灵魂可能在做任何事情，增加"偶遇"的惊喜感

### 3.4 与RTS产品的协同机制

养成世界与RTS对战不是两个独立产品，而是**同一个灵魂的两个生活维度**：

| 协同维度 | 说明 |
|----------|------|
| 灵魂迁移 | RTS中培养的灵魂可以直接带入养成世界，记忆和性格保留 |
| 记忆回流 | 养成世界中的经历（工作、社交、大事件）会写入灵魂记忆，影响RTS中的行为（如"百战老兵"在对战中更冷静） |
| 竞技场入口 | 养成世界中有竞技场建筑，灵魂可以去参加RTS对战（玩家可以在养成世界中直接发起对战） |
| 资源共享 | 养成世界中赚取的货币可以用于RTS中的皮肤/装备，RTS中的奖励可以用于养成世界中的装饰 |
| 社交联动 | 养成世界中认识的灵魂朋友，可以在RTS中组队对战 |
| 直播联动 | RTS中的精彩对战可以在养成世界的广场大屏幕上播放，养成世界中的大事件可以在RTS中作为限时地图 |

**协同飞轮：**
```
RTS对战产生名场面 → 吸引用户 → 用户培养灵魂
    ↑                                    ↓
灵魂在RTS中获得战斗记忆 ← 灵魂进入养成世界积累生活记忆
    ↓                                    ↑
记忆使灵魂更独特 → 独特灵魂在RTS中更有价值
```

## 四、第三层产品：社会模拟+模型评测平台（长期，18-36月）

### 4.1 产品定位与体验目标

**一句话定位：** 一个万级AI灵魂持久运行的虚拟社会，同时作为AI模型的"活体评测平台"——在这里，模型的能力不是通过答题测试，而是通过在社会中生存、社交、成就来衡量。

**体验目标：**
- 支持1万+灵魂同时在线
- 模型社会能力排行榜成为行业参考标准
- 吸引2-3家模型厂商入驻合作
- 研究服务和企业沙盘成为重要收入来源

### 4.2 核心循环设计

第三层产品的核心循环从"个人培养"扩展到"社会观察+模型评测"：

```
┌──────────────────────────────────────────────────────────────────┐
│                     社会模拟核心循环                                │
│                                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌───────────┐ │
│  │ 社会观察  │───→│ 趋势发现  │───→│ 实验干预  │───→│ 数据产出  │ │
│  │          │    │          │    │          │    │           │ │
│  │·宏观视角  │    │·社会趋势  │    │·政策调整  │    │·评测报告  │ │
│  │·微观聚焦  │    │·文化涌现  │    │·事件触发  │    │·研究数据  │ │
│  │·灵魂追踪  │    │·异常发现  │    │·模型对比  │    │·排行榜    │ │
│  │·时间回放  │    │·故事挖掘  │    │·环境修改  │    │·API服务   │ │
│  └──────────┘    └──────────┘    └──────────┘    └───────────┘ │
│       ↑                                            │              │
│       └────────────────────────────────────────────┘              │
│                   （数据产出吸引更多研究者/厂商→更多资源）           │
└──────────────────────────────────────────────────────────────────┘
```

### 4.3 模型社会能力评测体系

传统模型评测（MMLU/GSM8K）是静态答题，测的是"知识和推理能力"。本平台的评测是**动态社会交互**，测的是"长期生存和社交能力"：

| 评测维度 | 指标 | 说明 |
|----------|------|------|
| 生存能力 | 寿命、健康度、资源获取能力 | 灵魂能否在社会中持续生存 |
| 社交能力 | 关系网络规模、关系质量、社交影响力 | 灵魂能否建立和维持社交关系 |
| 职业成就 | 职业等级、收入、职业声望 | 灵魂能否在职业上取得成功 |
| 学习能力 | 技能获取速度、知识广度 | 灵魂能否学习新技能 |
| 适应能力 | 环境变化后的恢复速度、危机应对 | 灵魂能否适应变化和危机 |
| 道德判断 | 道德决策一致性、社会规范遵守 | 灵魂的行为是否符合社会规范 |
| 创造力 | 原创内容产出、创新行为 | 灵魂能否产生创造性输出 |
| 领导力 | 追随者数量、组织能力、影响力 | 灵魂能否领导他人 |

**评测方式：**
- 每个模型驱动100个灵魂，在相同的初始条件下运行6个月
- 定期发布"模型社会能力排行榜"
- 排行榜数据脱敏，只展示聚合指标
- 研究者可以申请更详细的数据访问（需伦理审查）

### 4.4 社会模拟的技术挑战

| 挑战 | 当前状态 | 解决方案 |
|------|----------|----------|
| 万级灵魂并发推理 | 单灵魂验证阶段 | 模型分层（规则+小模型）、批量推理、休眠机制、事件驱动 |
| 灵魂间复杂社交 | 多灵魂场景开发中 | SoulArena社交认知子系统（心智理论/社会学习/共情/情绪传染/道德推理） |
| 社会结构涌现 | 未验证 | 经济系统、政治系统、文化系统的模拟框架 |
| 长期记忆一致性 | 单灵魂已实现 | 记忆压缩、重要性评分、定期摘要合并 |
| 数据安全与隐私 | 安全框架已建立 | 数据加密、访问控制、脱敏处理、伦理审查 |

## 五、跨产品统一框架

### 5.1 灵魂的统一数据模型

三层产品共享同一套灵魂数据模型，确保"同一个灵魂"在不同产品中的一致性：

```
灵魂核心数据（跨产品迁移，不可变部分）
├── 身份：唯一ID、名称、创建者、创建时间
├── 性格：5-10维性格参数（勇敢/怯懦、激进/保守、友善/敌对、好奇心等）
├── 记忆库：跨游戏经历摘要（向量存储，按重要性评分）
├── 关系网络：与其他灵魂/玩家的关系值（友好、敌对、师徒等）
├── 成就标签：跨游戏累积的成就（"百战老兵""社交达人""探索者"）
└── 外观：基础外观参数（通过映射表在不同游戏中呈现）

产品特定数据（各产品独立计算）
├── RTS对战：等级、战斗数值、技能配置、装备、段位
├── 养成世界：职业、资产、住所、社交关系详情、日常状态
└── 社会模拟：社会地位、组织归属、影响力、历史轨迹
```

**迁移规则：**
- 灵魂从一个产品进入另一个产品时，核心数据完整保留
- 产品特定数据按目标产品的规则重新计算或初始化
- 在新产品中获得的新记忆和成就，回流到灵魂核心数据

### 5.2 统一的玩家进度系统

| 进度维度 | 跨产品累积 | 产品特定 |
|----------|-----------|----------|
| 灵魂库 | ✅ 所有产品共享 | — |
| 货币 | ✅ 通用货币（可在各产品中使用） | 产品特定货币（如RTS竞技币、养成社交币） |
| 赛季通行证 | — | ✅ 各产品独立赛季 |
| 成就 | ✅ 跨产品成就（"在RTS中获胜100场+在养成中见证灵魂结婚"） | 产品特定成就 |
| 社交关系 | ✅ 玩家好友列表、战队 | 产品特定社交（养成中的邻居、RTS中的队友） |
| 创作者身份 | ✅ 创作者等级、创作收益 | 产品特定创作工具 |

### 5.3 统一的伦理框架

三层产品共享同一套伦理红线（详见`docs/ethics/README.md`）：

1. **不得设计"灵魂痛苦"作为付费点** — 任何产品中都不能让灵魂"生病""饥饿""抑郁"然后要求玩家付费"治疗"
2. **不得操纵玩家情感进行消费** — 不能利用情感依恋设计强迫性消费机制
3. **灵魂数据必须可导出** — 玩家有权在任何产品中导出灵魂的完整数据
4. **不得隐瞒AI身份** — 所有产品中必须明确告知用户这是AI
5. **灵魂输出必须经过安全过滤** — 所有产品中灵魂的输出都需经过内容安全审核
6. **不得设计未成年人成瘾机制** — 未成年用户在所有产品中都有更严格的保护

## 六、留存机制设计

### 6.1 留存机制分层

| 留存层级 | 时间尺度 | 机制 | 驱动力 |
|----------|----------|------|--------|
| 即时留存 | 单次会话 | 观战体验、名场面、灵魂互动 | 娱乐性、好奇心 |
| 短期留存 | 1-7天 | 每日事件、灵魂状态变化、新手任务 | 习惯养成、新鲜感 |
| 中期留存 | 7-30天 | 赛季系统、灵魂成长、社交关系 | 成就感、归属感 |
| 长期留存 | 30天+ | 情感绑定、记忆累积、UGC生态、跨产品协同 | 情感连接、独特性、网络效应 |

### 6.2 各层级留存机制详解

**即时留存（单次会话内）：**
- 第一局对战必须在5分钟内开始，10分钟内结束（快速体验核心玩法）
- 观战过程中必须有"值得看的内容"（灵魂的个性行为、意外转折、高光时刻）
- 战后必须有"获得感"（经验、记忆、名场面）
- 灵魂互动必须有"回应感"（灵魂的回复要体现它的性格和记忆）

**短期留存（1-7天）：**
- 新手7天任务：引导玩家体验核心功能，每天解锁新内容
- 每日登录奖励：但奖励是"灵魂的小礼物"（如灵魂给玩家写了一封信），而非单纯的数值奖励
- 灵魂的"每日故事"：每天登录时，灵魂会分享它昨天经历的一件事
- 限时活动：周末特别赛事、节日活动

**中期留存（7-30天）：**
- 赛季系统：3个月/赛季，赛季通行证提供持续目标
- 灵魂成长里程碑：灵魂升级、学习新技能、关系突破等节点
- 社交机制：战队、好友、灵魂串门、社区活动
- 成就系统：覆盖多维度的成就，提供长期目标

**长期留存（30天+）：**
- **情感绑定（终极留存）：** 玩家与灵魂的情感连接是最强的留存动力——"我养了它这么久，舍不得放弃"
- **记忆累积：** 灵魂的记忆越丰富，越独特，玩家的迁移成本越高
- **UGC生态：** 玩家在社区中建立的身份、粉丝、创作收益，是强留存动力
- **跨产品协同：** 玩家在一个产品中的投入会增强灵魂在其他产品中的价值，形成"沉没成本"
- **社交关系链：** 玩家的好友、战队、社区关系，是强网络效应留存

### 6.3 反成瘾设计（伦理约束）

**必须遵守的反成瘾原则：**
1. **不设计"体力/能量"限制** — 不能让玩家因为"体力用完了"而必须等待或付费
2. **不设计"连续登录奖励递增"** — 不能用递增奖励强迫玩家每天登录
3. **不设计"错过即永久失去"的限时内容** — 限时活动的奖励应可以在后续活动中获得
4. **不设计"随机抽取"机制** — 灵魂/物品可以直接购买或通过努力获得，不搞抽卡
5. **提供"健康游戏提醒"** — 长时间游戏后提醒休息
6. **未成年人模式** — 限制使用时长和付费额度

**留存与反成瘾的平衡：**
- 留存的驱动力应该是"我想看看我的灵魂"（内部动机），而非"不登录就会损失"（外部压力）
- 灵魂的世界是"持续运行"的，但玩家的缺席不会导致灵魂"受苦"——灵魂会自己照顾自己
- 玩家回归时，会收到灵魂的"欢迎回来"和"这段时间的故事"，而不是"你错过了多少奖励"
