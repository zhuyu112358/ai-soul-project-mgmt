## 二、BUG-006根因修复分析（v4.90, commit 591a05c）

### 2.1 根因

```
uncaughtException handler:
  1. console.error(err.message)  ← err为null时此处抛出TypeError
  2. writeCrashLog(err)          ← 永远执行不到
  3. process.exit(1)
```

当EventEmitter发出`'error'`事件但没有传递error对象时，`err`为null/undefined。`err.message`在uncaughtException处理器**内部**抛出TypeError。Node.js规范：**uncaughtException处理器本身抛出异常时，进程立即以code=1退出**，且不再执行处理器中后续代码（包括crash日志写入）。

这完美解释了：
- ✅ 退出码始终为1
- ✅ 信号为null（不是被kill）
- ✅ 无crash日志文件（写入代码被跳过）
- ✅ 崩溃间隔不稳定（取决于何时触发null-err事件）

### 2.2 修复内容

1. **Null-err保护**：`safeErr = err || new Error('uncaughtException with null error')`，在任何属性访问之前
2. **Crash日志优先写入**：处理器第一行就写crash日志，在console.error/logger之前
3. **Flaky Test Fix**：修复了测试中的不稳定问题

### 2.3 修复验证状态

- **代码审查**：修复逻辑正确，覆盖了null-err边界情况 ✅
- **单元测试**：197测试全通过（含新增的flaky修复）✅
- **API测试**：v4.90运行2分钟，0错误，API全绿 ✅
- **长时间稳定性**：⏳ 待验证（之前崩溃间隔5-13分钟，需运行>15分钟确认）
